## Native End8 component and deferred Source admission

Independent planner/reviewer assessments select two final capability types
composing the existing private scene executor, not an unchecked Root factory
or second scene engine. `Scene::create` retains its matching live Manager
`EntryBorrow` check before allocation. Standalone `Component` admits only End8
and Credits17–20. Its creator-affine, nonmovable `ComponentModules` initializes
the existing ROM-derived data through the shared decoder, retains a real
independent lifetime epoch and leaves Root overlay generations zero. The
execution owner's lease is released last, after native, entry/domain and
remaining member retirement. Component results never acknowledge a Manager
entry; Root-only Camera/Photo, Report and Diagnostic services still require
their actual Manager.

Two genuine End8 defects were reached and corrected:

- The nonwaiting initializer registers the main process; that process admits
  Replay5/9/8 during the first actual OM update. The earlier unconditional
  immediate Replay check rejected the scene before any update. Heap/Input
  admission remains immediate; the first successful Source update must admit
  Replay before drawing. No eager host initialization, extra Source wait,
  manufactured retrace or direct Original-main invocation is added.
- The End8 bridge called the returning native input initializer but omitted
  the genuine C common-cache invalidator process. A separate phase-only
  executable displayed Pikachu but did not advance after ordinary A input.
  The bridge now follows Album/Gallery/Credits/Camera/Photo/Report: after the
  native leaf returns, install the existing C link9/kind0/priority0 process.
  Immediate scene admission also requires that real input process. The exact
  Original source bodies and rewrite counts remain fixed; only the affected
  initialized native unit and bridge/output/support identities change.

### Support authority and consumer review

Shared scene/module support identities are refreshed in all eight post-course
providers without changing their pinned Original authority. CameraCheck's
materializer previously ignored its declared `native_support`: the actual
old CLI accepted stale support bytes. It now verifies those bytes before
publication. The real updated configure/build succeeds; a separately declared
wrong-header digest rejects with `unadmitted native support:
src/post_course_scene.hpp` and publishes no output. This is an explicit
synthetic admission-negative fixture, not rewritten game evidence.

Ownership/capability review finds no concrete Root-gate or lifetime defect.
Independent loop review finds two consumer defects, now corrected: use
persistent `clock.stopped()` state to retry asynchronous native retirement,
and observe retained Progress failure before accepting final completion.
The consumer also reports actual public retirement attempts/pending returns
and preserves startup Progress failure rather than admitting a component
after stop. The worker/deadline observations above exercise those final
consumer corrections without promoting unobserved pending-return behavior.

All native targets build and all 61 local CPU CTests pass after the final
production and consumer corrections. Published `77f1cd6` passed
[all ten Linux/MSVC jobs](https://github.com/PhilosophiMoonbeam/35mmIsle/actions/runs/40048218009),
including the full host and new component consumer builds. This qualifies that
component cutover's builds, not subsequent dedicated-GAME-owner changes.
ROMs, generated GAME bodies, private executables, saves, pixels and PCM
remain unuploaded. Root24/Credits20 producers, full fresh campaign,
Windows 11 runtime and Original-fidelity gates are not closed by this section.
