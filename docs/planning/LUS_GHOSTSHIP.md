# libultraship and Ghostship integration plan

## Scope

Plan the native host boundary for 35mmIsle; do not import implementation, game assets, SDK material, or reference build configuration. libultraship (LUS) supplies host services and a display-list interpreter, not a complete N64 machine. Ghostship is a working **Super Mario 64 port**, not a blank generic template. Findings below are source observations; **proposed** decisions are not runtime results. `[INFERENCE]` identifies consequences not demonstrated by execution.

This document owns host/API, archive, rendering/readback (both live color focus and evaluation depth), controller, PCM-output and reference-reuse contracts. The authoritative Snap analysis and implementation roadmap own game-side symbol migration and scheduling implementation. No builds, tests, extraction, render/audio runs, or other proof gates were executed for this research.

## Findings

### Documentation versus actual support

| Documented claim / tempting assumption | Observed implementation | Integration consequence |
|---|---|---|
| Header-compatible SDK wrapper; bridge calls route automatically; guide suggests stubbing `osCreateThread` [guide][l-porting] | Repository exact-symbol search found `osCreateThread` only in that guide, not a thread implementation/declaration; `osStartThread`, `osStopThread`, `osDestroyThread`, `osSetThreadPri` had no hits. | No N64 priority scheduler or stack-preserving process implementation is established. Replace the SDK scheduler at an explicit game boundary; never call this automatic emulation. A link-only stub is not acceptable game behavior. |
| SDK message queues | [`osCreateMesgQueue`, `osSendMesg`, `osRecvMesg`][l-mesg] implement a ring buffer; `flag` is unused, empty/full return `-1`, and no synchronization/wakeup exists. `osJamMesg` rejects an empty queue and has no full-capacity guard. | Do not preserve blocking waits by calling these functions unchanged, or share these queues across host threads. Ordered game/process yields require their own reviewed execution contract. Do not infer SDK behavior from matching signatures. |
| VI / SDK timing | [`osCreateViManager`][l-vi] installs an SDL timer at **16 ms**, ignores requested event divisor in `osViSetEvent`, and sends a nonblocking queue message. Swap/mode/black/scales are empty; current/next framebuffer return null. [`osGetTime`/`osGetCount`][l-os] use steady-clock time in the N64 46.875 MHz domain; `osSetTimer` is a success-returning no-op. | Use a deliberate simulation tick and real presentation loop, not VI as the game clock or framebuffer authority. Separate monotonic host time, tick count, and video cadence. |
| SDK time-setting semantics | `osSetTime(t)` stores `steady_now + t`, while `osGetTime()` returns `steady_now - stored` [implementation][l-os]. | `[INFERENCE]` immediate nonzero `osSetTime(t)` does not produce the requested value (unsigned wrap is possible). Do not rely on it without a focused semantics test or correction. |
| PI/AI hardware calls | `osCartRomInit` returns null; `osEPiStartDma`, `osSetTimer`, `osAiSetNextBuffer` return success without the operation; `osAiGetLength` returns zero [implementation][l-os]. `osAiSetFrequency` is declared in [`os.h`][l-os-header] but exact-symbol search found no implementation in this checkout. | Replace ROM/DMA and AI submission at real native seams. Success codes do not prove delivery. ROM bytes must pass through checked extraction/resource ownership; PCM must reach the audio player explicitly. |
| Default Context factory can be called with all defaults | Header defaults window/deck to null; implementation returns null if either is absent [header][l-context-h], [implementation][l-context-cpp]. | Supply concrete Fast3dWindow and LUS::ControlDeck or compose components explicitly. Do not assume factory defaults provide a working/headless renderer. |
| Audio abstraction includes “mixing” | Guide explicitly says LUS exposes **PC audio drivers**, not N64 audio [guide][l-porting]; backend consumes S16 PCM [SDL implementation][l-sdl-audio]. | Snap synthesis, sequence/bank/sample decoding and its audio-command ABI remain game work. LUS is the output sink, not the synthesizer. |
| Fast3D GBI structures retain N64 binary layout | `Gwords` has two `uintptr_t` words; assertion uses `2 * sizeof(void*)`, despite the nearby inherited “exactly 64 bits” comment [definition][l-gfx-layout]. `GBI_FLOATS` changes vertex positions from short to float [definition][l-vertex-layout]. | Never cast ROM display-list bytes or serialized vertex records to host structures. Native display-list pointer arithmetic, allocation, memcpy lengths and exporter formats must be reconciled. |
| Portable color/depth capture follows from one API | Common [renderer interface][l-render-api] offers RGBA16 color readback and coordinate-set depth reads, but no color-read origin or readiness/context result. [Interpreter][l-fb-interpreter] ignores read origins; backend timing and packing differ [OpenGL][l-opengl-read], [Metal][l-metal-read], [Metal custom conversion][l-metal-pack]. | A screenshot is neither per-object live focus history nor Snap evaluation parity; a Null/headless host is not a real render proof. |

Ghostship concretely demonstrates the architecture: [`main`][g-game] creates the engine, initializes SM64 audio and memory, boots `thread5_game_loop`, and calls `thread5_iteration` inside `while (WindowIsRunning())`; `exec_display_list` forwards `SPTask.task.t.data_ptr` to `GameEngine::ProcessGfxCommands`. Its [engine construction][g-start] composes host components, [FinishInit][g-finish] chooses 32 kHz/512/1100 audio settings and `ucode_f3d`, and [audio thread][g-audio] calls **SM64's** `create_next_audio_buffer` before submitting PCM. This is proof of an explicit game-specific replacement path, not proof that calling Snap's original boot threads or audio tasks unchanged will work.

### GBI, renderer and photo contracts

**Compile-time GBI and runtime decoder are separate choices.** The guide lists `F3DEX_GBI_2`, `F3DEX_GBI`, `F3DLP_GBI`; CMake declares `GBI_UCODE` with `option(...)`, not a constrained string cache, and applies it **PRIVATE** to the library [CMake][l-cmake], [target definitions][l-target-gbi]. Runtime [`UcodeHandlers`][l-ucodes] separately lists `ucode_f3db`, `ucode_f3d`, `ucode_f3dex`, `ucode_f3dexb`, `ucode_f3dex2`, `ucode_s2dex`. Existence of an enum is not evidence for Snap's custom commands. Proposed build contract: explicitly pass the selected symbolic GBI value and matching definitions to game and library; record actual definitions on both sides. Do not trust an unqualified boolean option value or the default.

Snap's [task ucode table][s-ucode] includes `gspF3DEX2_NoN_fifo` and `gspL3DEX2_fifo`. Its [`gSPMvpRecalc`][s-mvp-op] emits `G_SPECIAL_1`; [matrix paths][s-mvp-use] combine it with `G_MW_MATRIX` writes. The current LUS [`GfxSpMovewordF3dex2`][l-matrix-gap] handles only light count, fog, segment and interpolated-segment indices: **there is no `G_MW_MATRIX` case**. This is a concrete missing operation in that path, not just an untested ucode name. Resolve the original combined-matrix semantics and implement/adapt the native equivalent before claiming these Snap render paths work; do not silently discard the writes. Photo processing also reconstructs objects/camera through [`initObjectsOnPhoto`][s-photo-replay], rather than merely capturing the live display. Preserve that reconstruction and pass ordering when selecting a host rendering seam.

Dispatch qualification: **`F3DEX_GBI_2` compilation plus `ucode_f3dex2` decoding is a research candidate, not a selected compatible Snap configuration.** For that candidate, [`ucode_handlers` maps `ucode_f3dex2` to `f3dex2Handlers`][l-dispatch-map]; the [table maps MOVEWORD][l-dispatch-table] to [`gfx_moveword_handler_f3dex2`][l-moveword-dispatch], which calls the function above with index/offset/data. [`gfx_step`][l-dispatch-step] checks extension/RDP maps before the selected ucode table. Full-checkout exact-symbol searches for `G_MW_MATRIX`/`G_SPECIAL_1` found header definitions/emission macros but no named implementation cases; this is supporting search evidence, **not a library-wide semantic impossibility claim**. The demonstrated absence is specifically the matrix-index case in `GfxSpMovewordF3dex2`; other decoders, translated commands or a future native matrix adapter require separate evidence. The final GBI/decoder combination remains blocked on source interpretation **and real capture parity**, including Snap's nonstandard matrix operations.

Ghostship globally defines `F3D_OLD`, `F3D_GBI`, `GBI_FLOATS`, `VERSION_US`, `ENABLE_RUMBLE`, `AVOID_UB` [build definitions][g-build]. **Reject wholesale copying**: these encode SM64 layout, microcode and game decisions. For Snap, select the representation only after canonical assets, dynamic GBI producers and interpreter consumers agree. Native pointer words must remain pointer-width; disk command fields remain specified-width and endian-defined. The stock [binary DisplayList V0 factory][l-dl-factory] reads a ucode byte, aligns to eight bytes, reads pairs of uint32 words into native Gfx, and recognizes selected expanded commands. [Vertex V0][l-vtx-factory] reads int16 positions field-by-field even when the native representation is float. Neither is a universal raw-ROM relocation/conversion layer.

Renderer capture has observable incompatibilities:

| Surface / operation | Source contract | Required Snap decision |
|---|---|---|
| `gDPCopyFB` / `gDPReadFB` | [GBI extension][l-fb-gbi] carries framebuffer IDs, CPU pointer, dimensions and optional byte swap. [Read interpreter][l-fb-interpreter] flushes, reads color, and explicitly ignores `ulx/uly`; the renderer read API has no origin. [Copy interpreter][l-fb-copy] selects a whole game viewport/dimension rectangle, not the detector's center tile. | Dedicated, correctly sized surfaces or an explicit region adapter; do not request a crop and assume it occurred. Decide image orientation, byte order and completion/context identity explicitly. The lower-level rectangle-copy API is a candidate, not proof that the stock commands implement this crop. |
| OpenGL color | Reads `(0,0,width,height)` RGBA8 and packs RGB by `>>3`, alpha by nonzero test [implementation][l-opengl-read]. [Rectangle copy][l-opengl-copy] adjusts Y using source height and `invertY`, then source/destination inversion. | Establish the actual framebuffer's orientation and canonical RGBA5551 values at each pass. An 8×8 read of the large framebuffer's origin is not the native center region; a screenshot cannot establish focus history. |
| Metal color | Screen FB 0 returns prior capture when available and requests another blit; [EndFrame][l-metal-deferred] copies from texture origin and retains a command buffer for later completion. Screen packing uses RGB `>>3`, alpha `a >> 7`. Custom FB's first read returns zeros, then uses a synchronous readback queue [read implementation][l-metal-read]; its [compute conversion][l-metal-pack] uses normalized RGB ×31, alpha `>0`, and source-texture-width output stride. | Screen/custom capture differ in timing **and** quantization/alpha. Waiting for a previous screen blit does not make it the current object's capture. An 8×8 dispatch over a larger custom texture is not a guaranteed tightly packed center tile. Never accept initial zeros, stale pixels or an unproved conversion as valid focus/photo data; backend adaptation remains conditional. |
| Depth | [Interpreter][l-depth] rescales coordinates, caches sampled results and queries current game/main FB; [OpenGL][l-opengl-read] derives a 16-bit value from depth/stencil, and the single-point GLES `glReadPixels` is compiled out. | Do not infer full-buffer, per-object, offscreen or GLES depth correctness. The GLES single-point branch leaves the read variable without a filled read path: block photo parity claims on that path. |
| Snap scoring | [64×48 buffers][s-score-buffers] contain image, current depth, twelve per-Pokémon depth buffers and twelve pre-Pokémon depth buffers. [Rendering][s-score-render] changes segment/depth targets; [CPU scoring][s-score-compare] tests sentinel `0xFFFC` and exact depth equality. | Correct full CPU-visible depth at each required pass is mandatory. Color readback plus occasional point depths is insufficient. `[INFERENCE]` a dedicated depth export, custom command handling and/or faithful software scoring pass may be required; select only from measured parity evidence. |

**Headless distinction:** resource parsing, deterministic simulation and PCM production can be exercised without audible output; Null audio proves no speaker/device behavior. A headless logic fixture proves neither shader/display-list interpretation nor capture. An offscreen/window-hidden context is useful only after proving it supplies the same real GPU renderer and readback surfaces. The inspected Fast3dWindow initialization creates a concrete window manager and rendering API [implementation][l-window-init]; no functioning headless photo surface is established by this audit. Retain a real OpenGL surface as the first rendering proof target; require separate DX11/Metal/GLES evidence before claiming those paths.

### Live-focus host contract

The game-side sequence and full photograph dependency explanation belong to [DECOMP: photograph dependencies](DECOMP.md#photograph-dependencies-blocking-not-optional-polish); fixture/oracle ownership belongs to [VALIDATION: behavioral acceptance matrix](VALIDATION.md#behavioral-acceptance-matrix), especially F07 versus F08. The host must satisfy **both** the following live-color obligations and the separate full-depth scoring obligations above; neither replaces the other.

| Host obligation (proposed; not implemented or measured) | Exact source boundary / acceptance requirement |
|---|---|
| Center region and row origin | Snap's [tile list][s-focus-tile] loads native pixels **x=156…163, y=116…123 inclusive** from the RGBA16 scene image, then copies to an 8×8 color target; [native dimensions][s-screen-size] are 320×240. Define canonical CPU element `(x,y)` as the corresponding native tile pixel, with consistent row order across captures. Prefer a canonical native-size focus source independent of window/high-DPI/GUI/interpolation changes; any alternative must prove the exact native pixel mapping, not resample the final presentation. For a normal bottom-left OpenGL source, the half-open source rectangle is x `[156,164)`, y `[240-124,240-116)` = `[116,124)`, with rows reordered to native orientation. Its symmetric center Y range makes a reversed-row bug easy to miss: use asymmetric pixel labels. Account for actual framebuffer `invertY` and viewport offsets rather than blindly applying this formula twice. |
| Per-object boundaries, not a final-frame capture | [Initialization][s-focus-init] saves the pre-Pokémon baseline; [render wrappers][s-focus-producers] save after each enabled, eligible model draw; [SaveRegion][s-focus-copy] records the corresponding object/ID/flags. Flush prior draw work and preserve a distinct tile for each such boundary before later draws alter the source. Region copying at these boundaries followed by deferred CPU transfer is a candidate; capturing only after all objects draw is not. Preserve scene render state/scissor when resuming. A correctly sized 8×8 staging target is useful only after an actual center copy, not after copying the screen origin. |
| Canonical RGBA5551, including alpha | Compare **64 complete u16 words**, packed `(r5 << 11) \| (g5 << 6) \| (b5 << 1) \| a1`, with explicit byte order and no RGB-only comparison. Snap's [packing definition][s-color-pack] takes the top five RGB bits and an already supplied alpha low bit; it does **not** specify how arbitrary host RGBA8/float alpha maps to the original rendered framebuffer bit. RGB8 `>>3` is a conversion candidate, not evidence that all backend render/quantization results match. Require each original packed color/alpha bit, including blended/transparent output, to match calibrated reference tiles; neither `alpha != 0` nor `alpha >> 7` is selected as universally faithful. Same-color or transparent overlapping geometry qualifies only when the actual packed output changes, not merely when an object covers the region. |
| Snapshot, frame and context identity | [InitDetector][s-focus-init] toggles contexts 0/1 and captures the scene snapshot **before** Pokémon drawing. [Main-camera producer][s-focus-enqueue] invokes [ProcessImage][s-focus-queue] after rendering to queue that detector context; [PostProcessImage][s-focus-post] consumes it to analyze and attach focus to the same snapshot, and [CopyInfo][s-focus-publish] publishes the analyzed context. The host capture record must retain simulation/snapshot identity, render submission identity, alternating context, ordered region index and object/ID/flags until consumption. Context 0/1 alone is not a unique frame identifier. Do not overwrite in-flight histories on context reuse or attach completion to the currently live world/snapshot. Asynchronous transfer may delay readiness, not retag data or change authoritative publication/shutter ordering. |
| GPU completion, then ordered CPU comparison | Original [DP full-sync handling][s-focus-completion] calls postprocessing before publishing the next framebuffer/task completion. Host flush/submission is not itself completion: establish completion of **all** retained tiles for that exact frame/context before CPU comparison, including first capture. [Comparison][s-focus-compare] visits consecutive regions in draw order, counts unequal packed pixels, accepts **≥32**, and overwrites the winner with each later qualifying object. Preserve that order and object association, even if transfers finish out of order. A zero-filled first read is not a valid completed black tile; an earlier completed frame is not the pending frame. No final-frame screenshot, raycast, nearest-object or object-ID buffer substitute is acceptable. |

**Why stock read/crop timing is insufficient:** ignored read offsets already prevent a direct center read; stock copy selects the full viewport; OpenGL origin/row mapping must be adapted; Metal screen capture observes an EndFrame image from an earlier request rather than each object boundary, and its custom first-read/packing path differs. The proposed resolving experiment below therefore evaluates an explicit region-copy/readback and completion adapter, not a promise that changing read dimensions or waiting one extra frame fixes the behavior.

### Resource archives, extraction factories and persistence

**Proposed:** a development **folder archive**, then release **O2R**, with identical logical paths and serialized resource contracts. Both are real [supported mechanisms][l-archive]; [FolderArchive][l-folder] indexes files and loads bytes from disk. Use an extensionless development root: automatic AddArchive chooses FolderArchive on an empty extension. Avoid placing packaged archives inside that root: initial path enumeration treats a directory containing recognized archives as a container of packages rather than the loose root. Do not promise automatic hot-reload: resource caching/invalidation and ownership need an explicit development experiment.

O2R is ZIP-compatible [README][l-readme]; MPQ/OTR is optional and not needed for the initial plan. Packaging does not perform conversion. [ResourceLoader][l-loader] keys factories by **format + numeric type + version**, rejects duplicate keys/conflicting names, and returns null for an unknown key. Its default registration contains Json V0 and Shader V0, not all Fast/game factories. It supports metadata (`type`, `version`, format and optional redirected path) and legacy headers [metadata handling][l-resource-meta]. Proposed archive manifest separates ROM identity, extraction/schema version and application version; do not collapse these into Ghostship's major/minor port-version comparison.

Ghostship registers [Animation/AudioBank/AudioSample/AudioSequence/Dialog/Dictionary, texture versions, Vertex/DisplayList/Matrix/Light and assorted SM64 data][g-factories]. These are a registration pattern, **not Snap data schemas**. Its [ROM identity table][g-extract-rom] recognizes SM64 JP/US hashes; its [extractor][g-extract] constructs Torch Companion with O2R/Binary export, and methods still named `GenerateOTR` actually emit O2R. Snap requires its own known-ROM identity policy, asset dependency/relocation rules, exporters and matching importers. Keep Torch pinned and game-specific; no claim that its SM64 rules can export Snap models, animations, sequences, photo metadata or overlays. A native micro-scene may use legally permissible original fixtures before all game exporters exist, but fixtures are not acceptance for actual game asset extraction.

Retain shared resource owners for every `GetPointer`/raw data consumer. Ghostship itself warns that purging cached sound resources while engine pointers remain live crashed, and instead invalidates only renderer texture caches [graphics integration][g-graphics]. Proposed invariants: no archive unload/cache purge while queued Gfx/audio/game pointers reference its data; no host addresses written into an archive; GPU submission and audio consumers finish before owners die. Folder and O2R imports must produce identical canonical values, not identical host memory images.

Ghostship [saves][g-saves] write SM64 save slots/global JSON, maintain duplicate in-memory slots and migrate an old `default.sav`; these are independent from LUS config persistence. Reject SM64 fields, JSON conversion and silent failed writes as the Snap save design. Proposed Snap save work must define its own byte/field schema, versioning and failure behavior from authoritative game semantics, including photo/album linkage. Copy the concept of app-scoped paths and explicit save lifecycle only.

## Reuse decisions

| Item | Decision | Boundary |
|---|---|---|
| Component ownership, explicit bridge binding, app-scoped paths | **Adopt conceptually** | Use current APIs, minimal owned services and one lifecycle; no copied compatibility facade. |
| Fast3D interpreter and GPU backends | **Adapt, conditional** | Only after opcode/GBI, live per-object focus-color/context and full photo-depth proof. No “supports Snap” claim from standard ucode enums. |
| LUS ControlDeck and PCM drivers | **Adopt host contracts** | Snap owns input tick semantics and synthesis. No SDK SI/AI completion emulation implied. |
| Folder development + O2R release archives | **Adopt** | Same paths/types/versions; game exporters/importers and deterministic override policy still required. No Nintendo payload in distributable source/release by default. |
| Stock texture/vertex/display-list factories | **Adapt selectively** | Prove exported field widths, endianness, ucode and relocation behavior per resource. |
| Torch / Ghostship extraction | **Adapt architecture only** | Pin tool; author Snap-specific rules under provenance policy. Reject SM64 hashes, configuration and type IDs as Snap defaults. |
| Ghostship entire 1,079-line game CMake | **Reject** | Reuse only reviewed dependency/target idioms; exclude SM64 source inventories, platform/mobile/networking/signing/interpolation options and generated-file assumptions. |
| Ghostship game loop/audio worker/save code | **Adapt conceptual seams, reject implementation transplant** | Preserve Snap process stacks/yields, fixed simulation ordering, audio semantics and album state instead of porting SM64 behavior. |
| SDK success-returning stubs | **Reject as completion** | Remove dependency on unused hardware operations or implement the exact required native behavior. Do not merely silence failures. |

### Dependency pin decisions and exact mismatch risks

**Proposed baseline:** integrate against audited standalone LUS `759b13401cd6903daa67a00a753066f791622e78`, not a floating branch and not an assumed Ghostship-compatible revision. Record Ghostship/Torch pins above as research/tool baselines, not hidden inherited runtime dependencies. Any change of LUS pin invalidates ABI/renderer/factory assumptions and repeats the affected proof experiments.

| Risk | Evidence / proposed response |
|---|---|

## Acceptance constraints

- A working host link is only the host milestone; unused stubs, a blank window or a headless tick loop are not end-to-end game completion.
- One canonical simulation tick owns process order, controller sampling, audio progression and photo state. Render interpolation/presentation cadence must not alter them.
- Every enabled renderer must prove real surface creation, capture completion, native packed image layout, ordered per-object live center-color histories with matching snapshot/frame contexts, and required full-depth semantics. Otherwise mark that backend unsupported for the affected behavior rather than returning fabricated data.
- Every archived resource has a stable logical identity, specified format/type/version, byte order, provenance and ownership lifetime. No raw host-pointer serialization or silent factory-version fallback.
- Game synthesis and save/photo data remain explicit Snap responsibilities. Library driver/config support is not evidence those responsibilities are implemented.
- Import/release remains gated on provenance and rights-specific review; original MIT work does not clear Nintendo/decomp/vendor material. No source/reference checkout was modified by this document.
