# Implementation roadmap

## Scope

Dependency DAG for a faithful, native Pokémon Snap desktop port on Linux x64 and Windows 11 x64. This document specifies implementation contracts, not a declaration of playability. The first fidelity baseline is the upstream US ROM; other ROM regions/revisions, consoles, mobile, web and other libultraship platforms require separate support decisions. MIT applies to original 35mmIsle work only. Source availability, ROM possession and matching builds do not establish redistribution permission.

Work-unit IDs below are stable import keys for Beads, not task-state tracking. An assigned integration owner imports these units and dependencies into Beads; no milestone closes from compilation alone. Every wave requires an independent reviewer and orchestrator-run smoke with the evidence specified in [VALIDATION.md](VALIDATION.md).

## Findings and invariants

1. **Authority before imports.** W00 approves material-specific provenance and rights, not a blanket license. A missing permissible implementation path blocks that import; research and original planning may continue. It never authorizes copied proprietary SDK code, ROMs, generated textures, music, microcode or screenshots.
2. **Reconcile before porting.** W01 records upstream symbols, unresolved assembly, local-fork deltas and approved transplant candidates. It also chooses a coherent host-template/LUS dependency baseline: deliberate adaptation to current LUS or a separately reviewed known-compatible template pin. The audited current [`DrawAndRunGraphicsCommands` has two arguments](https://github.com/Kenix3/libultraship/blob/759b13401cd6903daa67a00a753066f791622e78/include/fast/Fast3dWindow.h#L103-L110); template APIs/options cannot be assumed drop-in. Matching original behavior, not accumulated host hacks, is the acceptance baseline.
3. **One serialized gameplay owner, distinct service clocks.** Gameplay owns game-originated sound requests, state mutation, snapshots and persistence events. W04 freezes independently retrace/sample-paced audio and input service phases, their observation order, queue coalescing and mapping to simulation updates. Device callbacks never advance gameplay; audio progression is not forced one-to-one with completed updates.
4. **Typed data boundaries.** ROM offsets, DMEM/segment/resource tokens and serialized 32-bit values are not host pointers. Decode immutable wire data once; preserve widths, alignment and endian rules. Tagged null, root value 1 and current-framebuffer value -1 selectors are semantic alternatives, not addresses. Check native offsets, strides and allocation arithmetic independently of wire layout; LP64 and LLP64 must both work. Reset contracts restore initialized overlay data as well as BSS and distinguish scene heaps, player-only audio reset, full audio-asset reset and persistent state.
5. **Rendering is gameplay.** W06 separates faithful raster execution from faithful export and retains an architecture-neutral canonical feedback boundary. Exact live-focus words and raw packed scoring-depth words, per-pixel predicates, counts and decisions are default acceptance. Original RDP AA is not optional host MSAA. Backend/decoder selection remains unproved; a different observational-equivalence contract requires separate review proving downstream raster, copy and predicate behavior, not merely final scores.
6. **No shipped no-ops.** W07 may be a private, explicitly limited host scheduling experiment. A blank window, linked executable, hard-coded photo, silent audio, discarded save or disabled subsystem is neither playable nor a release candidate. Temporary experiment scaffolds are removed or replaced before their dependent behavior gate closes.
7. **Contract freeze, then parallelism.** One integration owner controls shared build manifests, ABI headers, scene registry, event definitions and dependency pins. Slice owners do not independently change those surfaces. Contract changes travel through that owner and invalidate affected evidence; migrations update every consumer without compatibility shims.

Research units close with evidence and a chosen contract, not a mock implementation. Failed hypotheses block their dependent production behavior. Beads remains status SSOT; all W00–W15 parent-completion dependencies remain binding. Earlier bounded nonplayable falsification is allowed only as a separately tracked child/spike with reviewed, versioned admitted prerequisite evidence: per-material/per-use rights, actual inputs, owned surfaces, coverage, falsifier, result and invalidation rules recorded before execution. Accepted narrow evidence neither closes a parent nor marks blocked production ready, authorizes imports or permits full original-scene boot. A shared-contract change invalidates affected evidence. This artifact admission is not a production-DAG bypass; full W12 still precedes full W08.

## Reuse decisions

| Disposition | Material/pattern | Boundary |
|---|---|---|
| Adopt | Authoritative upstream behavior, symbols and scene/data inventory as research baseline | Subject to W00 import rights; authority is not a license grant. |
| Adopt | Local, ROM-driven tick replay and semantic differential evidence | Publish original tooling/manifests only after rights review; no bundled original payload. |
| Adapt | Pinned LUS lifecycle/input/render/audio/resource facilities | Require Snap-specific ABI, scheduling, command and scoring proofs; no claim that library availability establishes game compatibility. |
| Adapt | Mature-port separation of serialized addresses/resources from host handles, and asset-free packaging patterns | Carry only rights-cleared design/implementation; validate against Snap rather than Zelda behavior. |
| Reject | Dirty fork as canonical source; blanket MIT relicensing; copying proprietary SDK; generated inventory as completeness | Preserve references read-only; record allowable individual reuse. |
| Reject | Callback-only process substitution, render-frame RNG, GPU screenshot scoring, silent/device/save no-ops | These change named original behaviors or disguise missing implementation. |

## Prioritized risks and open decisions

Priority orders investigation, not delivery estimates. Detailed fixture procedures and acceptance thresholds are in VALIDATION.

| Priority / risk | Blocking units | Exact resolving experiment / decision evidence |
|---|---|---|
| P0 — source/payload rights unavailable | W00, all imports, W15 | Enumerate each proposed file/tool/binary/payload, upstream notice and applicable grant; obtain rights-specific review or implement an approved original alternative. ROM ownership and GitHub publication do not clear this. |
| P0 — custom ucode or CPU depth not faithfully supported | W06, W10, W14 | Capture command streams plus original 64×48 current/per-subject/pre-subject depth for overlapping subjects; run candidate interpreter on every claimed backend; compare sentinel, equality classes, subject choice and score at one-pixel thresholds. | P1 — coroutine/order/tick semantics changed | W04, W07, W09 | Trace wait/resume, spawn, self-delete, delete-next, pause/unpause and priorities in a real actor sequence; replay through the proposed host scheduler with fixed tick input and compare ordering/RNG after every tick. | P1 — decoder or relocation corruption | W05, W08, W12 | Decode known course/photo/audio assets; mutate lengths, offsets, endian markers and relocation targets locally; reject safely before publishing partially resolved resources. Repeat unload/reload to detect stale references. |

| P1 — audio clock or synthesis differs | W12, W14 | Compare original event ticks and calibrated PCM for sequence loops, voice stealing, cries, reverb and transitions; run full-course device-rate conversion and stalls; measure sample drift without coupling it to gameplay. |
| P1 — reference itself is wrong or nondeterministic | W02, all fidelity gates | Repeat cold-boot captures, document initial state and time-derived RNG; cross-check sensitive scoring/audio cases on an independent reference/hardware. Quarantine disagreements before declaring port defects or widening tolerances. |
| P2 — packaging/OS backend capability assumed | W14, W15 | On clean native Linux x64 and Windows 11 x64 systems, extract from local known ROM, play full loop, save/reload and exercise actual backend/readback/device path. Availability in LUS is not a support promise. |

No supported backend, architecture beyond the release matrix, alternative ROM, printer peripheral or enhanced presentation mode is implicitly approved. Unsupported peripheral handling must be truthful and must not block the original core loop; its intended policy is a separate scope decision. Final completion means W13 behavior, W14 qualification and W15 lawful packaged operation, with no required gaps—not a blanket “100% accurate” claim.
