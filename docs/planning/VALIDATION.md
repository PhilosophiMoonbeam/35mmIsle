# Behavioral validation and release gates

## Scope

Proposed proof obligations for the ROADMAP work units, from authority review through a native Pokémon Snap release on Linux, Windows and macOS. No gate, build, test, formatter or runtime experiment was executed in preparing this document. Compilation, an initialized window or a synthetic render demonstrates only that limited operation; none proves a playable or complete game.

The initial original-region baseline is US ROM SHA-1 `edc7c49cc568c045fe48be0d18011c30f393cbaf`. Other revisions/regions and broader LUS platforms are deferred decisions, not accepted compatibility. Original behavior is evaluated against provenance-controlled local ROM fixtures; public artifacts contain no ROM or extracted game assets. A failed rights gate blocks imports/releases even if the technical gates pass.

## Findings: non-negotiable evidence boundaries

- Game state, capture state and audio event time are keyed to original simulation ticks; host presentation and device callbacks are consumers, not alternate game clocks. Original tick draining and time-derived random helpers remain explicit W04 questions.
- Photo scoring and shutter focus observe render outputs on CPU. CPU/RDP-equivalent full depth, per-object 8×8 packed-color history, frame/context association, custom commands and photo reconstruction are game semantics, not optional visual polish.
- Persisted bytes must use explicit schema, widths, endian and version, never native pointer sizes, C padding or compiler bitfield layout. Original checksum/version behavior and native transaction integrity are distinct obligations.
- Differential equality proves only the fixtures exercised. All acceptance records identify coverage and unresolved uncertainty; no blanket “100% accurate” statement follows from this plan.

## Reusable original-ROM fixture process

### Provenance and non-distribution

| Step | Procedure / retained evidence | Hard boundary |
|---|---|---|
| Authority | Record Snap/LUS commits, rights disposition, tool/oracle versions, local ROM normalized SHA-1, input byte order and selected region | A known hash proves identity, not lawful possession or import permission. Do not acquire or distribute ROMs. |
| Normalization | Read only the user-provided ROM; recognize supported byte order explicitly and normalize to the authoritative z64 identity before extraction | Wrong region, revision, truncated image and unsupported order fail before assets enter cache; never patch an unknown ROM into the expected hash. |
| Baseline capture | Run original ROM with a documented trusted reference, cold boot or precisely identified local save, tick-indexed input, reset/clock/seed conditions and original viewport/audio settings | Reference choice is unresolved until W02. Cross-check scoring/audio-sensitive samples with an independent reference or hardware; an emulator is not automatically ground truth. |
| Repeatability | Repeat identical initial-state replay; retain divergence point for clock-derived randomness. Freeze controlled clock behavior only if its mapping to original behavior is documented | Never silently reseed the retail game or relabel uncontrolled captures deterministic. Non-repeatable captures remain observational evidence until explained. |
| Capture package | Store local input trace, scene/tick markers, semantic snapshots, original score fields, private color/depth captures, audio event/PCM records and save semantic dumps | ROM, extracted assets, game imagery/audio, microcode, original save payloads and raw snapshots containing them remain private. Even derived public material receives rights review. |
| Reuse | An original fixture manifest describes expected ticks/events, hashes and extraction/capture recipe; each developer regenerates local payload from their own approved ROM | Public repository/releases contain original tooling, reviewed manifests and non-payload diagnostics only; no asset cache in CI artifacts or crash attachments. |
| Comparison | Run the same input and initial semantic state through the candidate; compare canonical fields rather than addresses/padding; retain first differing tick and renderer command/asset identities | Cross-platform save loading uses the native schema, not a binary oracle memory dump. A save-state is a private capture accelerator, not the sole cold-boot proof. |
| Artifact policy | Keep local evidence by fixture ID plus ROM/source/compiler/OS/backend/build identities; public gate report includes pass/fail, coverage and sanitized mismatch explanation | Exclude host usernames/paths/device identifiers and protected payload from published logs; asset-free package audit is mandatory. |

The fixture format must name simulation tick, input sampling phase, scene/state reset, RNG seed and relevant clock source, camera/capture tick, chosen photo/evaluation operation and save generation. Canonical object identities are stable logical IDs, not host pointers. Native event order is compared before pixels so a scheduler failure is not mistaken for a shader failure. W02 also captures the original-reference audio command/event/PCM corpus, bank/sequence/sample identities and producer timing from startup through ending, including voices, reverb, quality/mono settings and transitions. W12 executes that local corpus against real decoded assets and W07 lifecycle contracts before playable native scenes exist; it is not a prerecorded playback substitute. The process is reusable for additional regions only after separate identity, semantics and rights review.

### Comparison policy

| Domain | Proposed comparator | Stop/go rule |
|---|---|---|
| Discrete game state | Exact scene transitions, process/action order, input edges, RNG output sequence, progression flags, subject IDs, score fields and persisted logical values | Any unexplained difference blocks that fixture. Random/time-dependent initial state must be controlled or explicitly recorded. |
| Scoring render outputs | Exact original u16 sentinel/equality classes, center/unobstructed counts and derived evaluation decisions; require byte equality where the chosen original-compatible path promises it | No aggregate image score hides a one-pixel framing/occlusion change. Any scoring mismatch blocks photos/backend qualification; choose a demonstrated deterministic evaluation path or correct the backend. |
| Visible color/geometry | Original-resolution captures plus named geometry/texture/material/UI landmarks; compare masks and packed color before enhanced presentation | Pre-register tolerances from reference repeatability/quantization measurements. No arbitrary threshold or post-failure widening. Visual tolerance cannot relax score/state comparisons. |
| Float/camera behavior | Canonical camera/path/pose values and visible outcomes at specified ticks; preserve original operations where behavior depends on rounding | W02/W04 establish justified numeric tolerances from original/reference evidence. Exact threshold-triggered behavior still matches. |
| Audio | Exact event tick/order, sound/sequence identity and loop boundaries; compare calibrated PCM/envelope/pitch/channel behavior at original synthesis rate separately from device resampling | Timing/envelope tolerances require measured reference variability and documented device buffering. Reject persistent drift, missing voices/events, wrong pitch or obvious artifacts; do not claim waveform equality without proof. |
| Save | Canonical schema values, photo metadata/regeneration and generation integrity; transaction is entirely old or new | Truncation, mixed generation, silent reset, false write success or host-layout dependence blocks persistence. |

Threshold definitions are prerequisites to a fixture's acceptance, not optional later tuning. Record whether a comparison is exact, calibrated-tolerance or observational. Oracle disagreement blocks a fidelity claim until resolved; it is not permission to suppress the mismatch.

### Full Snap loop smoke

The orchestrator runs a repeatable vertical slice on the integrated wave: cold launch → original title/new or loaded game → course selection → real course movement and interactions → camera/zoom/shutter → course end → photo selection → Oak evaluation → report/album operation → native save → quit process → cold relaunch → verify score/photo/name/comment/progress → replay course. Waves 0–2 produce research/ABI/assets/isolated-render evidence, and wave 3 W07 is a nonplayable scheduler/lifecycle experiment, not original scene startup. Wave 4 W12 proves full native audio with original-reference command/event/PCM and real-device/readiness/shutdown evidence; disjoint renderer experiments remain nonplayable and cannot hide absent required services. Wave 5 W08 first boots original title/menu/Beach with real audio, wave 6 W09 replays interactive Beach, wave 7 W10 adds capture/selection/Oak and integrated sound-event qualification, and wave 8 W11 adds album/report/save/cold reload. Wave 9 W13 extends the smoke to every course, final progression, ending/credits and all integrated audio; waves 10–11 qualify platforms and packages. Every available original-scene prefix includes real original music/cries/effects as applicable from its first boot. Missing later stages cannot be marked passed, playable-complete or release-ready.

## Platform, compiler and presentation matrix

Proposed initial qualification targets: desktop x86-64 Linux/Windows and arm64 macOS. Architecture breadth is a release decision, not an implicit promise of every architecture supported by LUS. If another architecture is advertised, it receives its own native cell. Backend availability must first be confirmed for the pinned dependency/build; the candidate choices below are not assertions of completed support.

| Native platform | ABI / candidate compiler cells | Candidate renderer cells | Required evidence |
|---|---|---|---|
| Linux x86-64 | LP64; GCC and Clang | OpenGL; any additional advertised backend independently | F01–F14; real desktop input/audio/save/package; original semantic/score fixture parity across compilers. |
| Windows x86-64 | LLP64; MSVC and clang-cl (GCC/Clang results elsewhere ensure a second compiler family) | Direct3D 11 and OpenGL if both advertised | F01–F14 on actual Windows; pointer/long conversions, disk replacement/path semantics; score/readback parity for every advertised backend. |
| macOS arm64 | LP64; Apple Clang | Metal and OpenGL only if explicitly retained/available | F01–F14 on actual macOS; package launch/write locations, graphics/audio device path and calibrated parity. |

Minimum compiler-family coverage is GCC-compatible and MSVC-compatible, not two versions of Clang alone. Debug and release/optimized builds must both preserve fixture semantics; sanitizer-supported ABI/asset/process/save runs target plausible UB/lifetime edges, not a blanket all-platform sanitizer promise. Cross-compilation or CI compilation does not replace native runtime evidence.

Original-resolution 4:3 evaluation is mandatory regardless of window aspect ratio, render scale, MSAA or presentation interpolation. Qualify default presentation first, then any advertised option with F06–F08 parity. Vsync on/off and 30/60/120/144 Hz/uncapped presentation exercise simulation independence; these are validation stimuli, not an assurance every machine reaches those rates. Under load, measured slow-frame policy must remain explicit. Enhanced visuals cannot alter game-visible color/depth buffers, timing or original input semantics.

## Save transaction and version acceptance contract

Proposed native schema: a versioned envelope identifying game/ROM baseline, canonical payload length and integrity, generation identity, and explicit endian/width encodings. Photo/report/album data preserve original semantics (S9), not host memory layout. W11 decides whether to retain a compatible original payload or migrate fields into an original native encoding; compatibility claims require real round-trip evidence.

| Operation | Required semantics / resolving proof |
|---|---|
| Commit | Write complete replacement into a same-filesystem temporary file; verify length/integrity; flush file data; atomically replace only after completion. Specify and exercise directory/metadata durability and OS-specific replacement behavior. No premature UI success. |
| Crash/fault | Interrupt before/after write, flush, replace and durability boundary. A loader accepts complete last committed or complete new generation; an incomplete temp never supersedes valid state. Document residual power-loss limits per filesystem/OS rather than promising impossible universal atomicity. |
| Recovery | Preserve corrupt/unknown-version bytes and last known-good state; offer explicit recovery/error policy. Never silently start a new game and overwrite evidence. Simultaneous writers must be rejected or serialized with an explicit lock policy. |
| Version migration | Supported old schema has explicit validated conversion and round-trip fixtures; future/unknown schema is rejected without mutation. New schema versions require a work unit and changed fixtures, not a raw-struct compatibility assumption. |
| Cross-platform | Linux/Windows/macOS load the same native schema into identical canonical state and regenerate the same original photos; host pointer/bitfield/locale differences are absent. |
